Project Overview

This case study demonstrates how I investigate and resolve intermittent payment API failures affecting specific merchants. It highlights the importance of log correlation, payload analysis, and collaboration with engineering teams in a high-volume financial environment.

What This Case Demonstrates

  • Isolating issues in distributed systems

Investigation

During peak hours, ~2% of payment transactions from specific merchants began failing at the API layer.

Steps Taken

  • Acknowledged alert and joined incident bridge for initial triage.
  • Queried Splunk and Dynatrace for elevated error rates, filtering by endpoint, merchant ID, and error codes.
  • Identified a clear pattern limited to specific merchants.
  • Reproduced the issue in Postman using real failing payloads captured from logs.
  • Compared successful vs failing requests to isolate differences in the payment_reference field.
  • Analysed distributed traces to pinpoint the failing downstream validation service.

Root Cause

The merchant-generated payment_reference field contained unexpected formats (special characters or length variations) that were not fully handled by the downstream validation service. This resulted in a 400-level error that was poorly propagated upstream.

Resolution & Improvements

  • Updated validation logic to handle edge cases while preserving security.
  • Improved error messaging with better context for merchants and internal teams.
  • Added targeted monitoring alerts for this error pattern.
  • Enhanced runbooks with reproduction steps and payload examples.
  • Worked with engineering to add contract testing for future changes.

Support Engineer Insight

This case highlights how small differences in merchant data can expose edge cases in shared services. Strong observability, methodical payload analysis, and clear communication are essential when supporting high-volume payment platforms.

In production support roles like those at Circle, being able to quickly isolate whether an issue is in the API layer, a downstream dependency, or merchant-side data is a critical skill.
